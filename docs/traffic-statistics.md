# 网站访问统计

顶栏“统计”指向 `/stats/`。提供近 24 小时、7 天和 30 天的 PV 增长及可切换趋势图，复用现有不蒜子服务的域名累计浏览量。它不是时间段去重访客数。

`scripts/collect-traffic.mjs` 使用 GET 只读查询，不增加访问次数。现有每小时第 7 分钟的 `sync-post-dates.yml` 顺带采样，不新增调度频率。采集失败保留旧数据且不阻断 CMS 日期同步。GitHub 调度可能延迟，页面显示最近采样时间，超过 3 小时提示滞后。

快照存储在独立 `analytics-data` 分支的 `history.json`，仅有时间与总次数，不记录 IP、访客标识或个人信息。采样提交不会触发 master 的网站构建。页面直接只读读取公开数据，不暴露写入凭据。快照保留约 35 天，每 30 分钟内重复采集会跳过；统计源数值下降时开启新段并提示重置。

所有区间以最近采样时间为终点，使用区间内第一个实际采样作基准，不插值或推测访问发生时刻。只有一个样本时显示等待；不足周期时标明覆盖小时数与“数据积累中”；长采样间隔也明确提示。启用前的历史不能从累计值还原。

验证：`node --experimental-strip-types --test scripts/traffic-stats.test.mjs`。手动采集使用已有小时工作流的 Run workflow。需要立即更新页面时点击“刷新数据”，它只读取已采集记录，不强制采样。

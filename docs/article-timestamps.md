# 文章自动时间

保存文章产生 Git 提交后，部署流程从 master 的完整第一父提交历史推算时间，并只回写 frontmatter 的 `published` 和 `updated`，不重新序列化正文。

- 新建草稿：`published: null`，`updated` 是保存提交时间。
- 首次关闭草稿：`published` 是该次公开保存的时间。
- 公开状态下修改：保持 `published`，更新 `updated`。
- 改回草稿：清空 `published`；再次公开重新计时。
- 单纯重新部署或自动日期回写：不改变日期。
- 内容无变化、没有产生文章改动的保存：不刷新修改日期。
- 只重命名、内容未同时改写时保留公开时间；删除后重建视为新文章。

时间保存为带 `+08:00` 的 ISO 时间戳。公开时间代表公开状态保存到 master 的时刻，网页实际可访问仍取决于部署成功；不把等待部署的时长算入保存时间。旧文章根据仓库可追溯的提交历史回填，不伪造更早的部署时刻。媒体文件单独替换但正文没有变更，不视为文章保存。

CMS 时间字段只读。保存后等待工作流完成再刷新；若没有触发工作流，点击既有“发布网站”。不要从未刷新的旧编辑页再次保存覆盖最新版本。工作流回写使用非强制 push；如果同步期间 master 已有新提交，当前流程会失败而不会覆盖它，下一轮或手动重试会以最新 master 计算。

本地预览：`node scripts/sync-post-dates.mjs`。写入：加 `--write`，要求文章正文已提交且 Git 不是浅克隆。测试：`node --test scripts/sync-post-dates.test.mjs`。

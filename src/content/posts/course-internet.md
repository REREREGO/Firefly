### 第一章 数据链路层

#### 理解冲突域与广播域的概念

- 碰撞域（collision domain）又称为冲突域，是指网络中一个站点发出的帧会与其他站点发出的帧产生碰撞或冲突的那部分网络。

    碰撞域越大，发生碰撞的概率越高。

![image\.png](/Firefly/uploads/course-internet/image-21.png)

    广播域（broadcast domain）：指这样一部分网络，其中任何一台设备发出的广播通信都能被该部分网络中的所有其他设备所接收。

![image\.png](/Firefly/uploads/course-internet/image-13.png)

    以太网交换机的每个接口都处于一个独立的碰撞域（或冲突域）中，但所有计算机都处于同一个广播域中。

![image\.png](/Firefly/uploads/course-internet/image-24.png)

#### 理解并掌握集线器与交换机的差别

1. **集线器**

    1. 本质：传统以太网采用星形拓扑，在拓扑中心增加一个可靠性非常高的设备，叫做集线器。集线器本身必须非常可靠。现在的**堆栈式**集线器有4\-8个集线器堆叠起来使用。集线器一般有少量的容错能力和网络管理能力。

![image\.png](/Firefly/uploads/course-internet/image-29.png)

    1. 特点

        1. **使用集线器的以太网在逻辑上仍然是一个总线网，各站共享逻辑上的一条总线，使用的还是CSMA/CD协议**。网路中的各站必须竞争对传输媒体的控制，并且**在同一个时刻至多允许一个站发送数据**。

        2. 一个集线器有许多的**端口**。因此，一个集线器很像一个**多端口的转发器**。

        3. **集线器工作在物理层**，它的每个端口仅仅**简单地转发比特**，**不进行碰撞检测**。

        4. 集线器采用了专门的芯片，进行自适应串音回波抵消。这样就可以使端口转发出去的较强信号不致对该端口接收到的较弱信号产生干扰。每个比特在转发之前还要进行再生整形和重新定时。

    2. **交换机**

        1. 本质：**交换式集线器**，也称**以太网交换机**或**第二层交换机**，强调这种交换机**工作在数据链路层**。以太网交换机一般都有多种速率的端口。

        2. 特点：

            1. 交换机实质上就是一个多端口的网桥，通常都有十几个或更多的端口，与物理层的转发器、集线器有很大的区别。以太网交换机的每个端口都直接与一台单机或者另一台交换机相连，并且一般工作在**全双工方式**。相互通信的主机都**独占传输媒体，无碰撞地传输数据**。每一个端口和连接到端口的主机构成了一个碰撞域，具有N个端口的以太网交换机的碰撞域共有N个。

            2. 以太网交换机的端口还要存储器，能在输出端口繁忙时把到来的帧进行缓存。如果两台主机同时对另一台主机都发送帧，那么这台主机的端口繁忙时，发送帧的两台主机的端口会把收到的帧暂存一下，以后再发送出去。

            3. 以太网交换机是即插即用的设备，其内部的帧**交换表**，是通过**自学习算法**自动逐渐建立起来的，这种交换表就是一个**内容可寻址存储器CAM**。

            4. 最大优点：一个用户在通信时是独占而不是和其他网络用户共享传输媒体的带宽。（对于总容量，集线器是标定值，交换机是累加）

    3. 比较：

        1. **集线器（Hub）**工作在物理层，没有相匹配的软件系统，是纯硬件设备。集线器主要用来连接计算机等网络终端。

    交换机（Switch）工作在数据链路层，稍微高端的交换机都有一个操作系统来支持。和集线器意义主要用于连接计算机等网络终端设备。

#### 计算 CRC

![image\.png](/Firefly/uploads/course-internet/image-22.png)

1. 发送端先把数据划分为组，每组k个比特，在数据后添加n位冗余码，一共发送\(k\+n\)位。

2. 获取冗余码：

    1. 在数据后面添加n位的0，得到M，与双方事先商定的\(n\+1\)位除数P，用模2加运算进行除法运算，如上图。

    2. 得到的最终的n位的余数R，作为FCS。

3. 接收端把\(k\+n\)位的数据和冗余码，用先前的算法与除数P进行运算，检查得到的除数R。如果R=0，则判定这个帧没有差错，接受；如果R≠0，判定这个帧有差错，就丢弃。

#### 理解链路层的广播地址与网络层的广播地址的差别

- 检查流程：

    1. 在同一 VLAN 内发送 ARP 请求，观察目的 MAC 为 FF:FF:FF:FF:FF:FF 的帧仅在二层域内可见。

    2. 发送 255\.255\.255\.255 的 IP 报文，观察路由器是否转发。

#### 理解并掌握 ARP 协议过程

![image\.png](/Firefly/uploads/course-internet/image-5.png)

- 

1. ARP进程在本局域网上**广播**发送一个ARP请求分组。内容为“我的IP地址是xxxx，MAC地址是xxxx，我想知道IP地址为xxxx的主机的MAC地址”。

2. 局域网上的所有主机的ARP进程都收到此ARP请求分组。

3. 主机B的IP地址与ARP请求分组中要查询的IP地址一致，就首先这个ARP请求分组，并向主机A发送ARP响应分组（**单播**），同时在这个ARP响应分组中写入自己的MAC地址。内容为“我都IP地址是xxxx，MAC地址是xxxx”。

4. 主机A收到主机B的ARP响应分组后，就在其ARP高速缓存器中写入主机B的地址到MAC地址的映射。

5. 当主机A向B发送数据报时，很可能不久后主机B要向主机A法案送数据报。为了减少网络上的通信量，主机A在发送其ARP请求分组时，把自己的IP地址到MAC地址的映射写入ARP请求分组。当主机B收到ARP请求分组时，就把主机A的地址映射写入主机B的ARP高速缓存中。

#### 掌握 ARP 报文格式

![image\.png](/Firefly/uploads/course-internet/image-6.png)

- 硬件类型：指明了发送方想知道的硬件接口类型，以太网的值为 1。

- 协议类型：表示要映射的协议地址类型。它的值为 0x0800，表示 IP 地址。

- 硬件地址长度和协议长度：分别指出硬件地址和协议的长度，以字节为单位。对于以太网上 IP 地址的ARP请求或应答来说，它们的值分别为 6 和 4。

- 操作类型：用来表示这个报文的类型，ARP 请求为 1，ARP 响应为 2，RARP 请求为 3，RARP 响应为 4。

- 发送方 MAC 地址：发送方设备的硬件地址。

- 发送方 IP 地址：发送方设备的 IP 地址。

- 目标 MAC 地址：接收方设备的硬件地址。

- 目标 IP 地址：接收方设备的IP地址。

### 第二章 网络层

#### 理解并掌握 IP 报文格式，尤其是 IP 报文各字段的作用与含义

![image\.png](/Firefly/uploads/course-internet/image-18.png)

1. IP数据报的格式说明协议IP都具有什么功能。描述首部格式的宽度是32位。

    1. IP数据报由两部分组成：首部和数据部分；

    2. 首部部分由两部分组成：

        1. 固定部分：长度是**固定的**，共20字节，是IP数据报必须有的；

        2. 可变部分：是一些**可选字段**，长度是可变的。

2. **IP数据报首部的固定部分中的各字段**

    1. **版本 **占4位，指协议IP的版本。

    2. **首部长度 **占4位，克表示的最大十进制数是15。首部长度所表示的数的单位是32位字长（4字节）。用于首部最短20字节，故首部长度至少为5。首部长度都是4字节的整数倍，如果不是则用填充字段加以补充。

    3. **区分服务 **占8位，用来获取更好的服务。不使用区分服务时，一般不使用这个字段。

    4. **总长度 **占16位，就是首部和数据之和的长度，单位为字节。数据报长度至多为65535字节。由于**最大传送单元MTU**的限制，数据报的总长度（指的是单个数据报的长度而不是这个字段的限制）不能超过下面数据链路层所规定的MTU值限制。可以进行分片来解决，数据报首都中的“总长度”指的是**分片后每个分片**的首部长度与该分片的数据长度的总和。

    5. **标识 **占16位。IP软件在存储器中维持一个计数器，每产生一个数据报，计数器就加一，并将此赋值给标识字段。标识不是序号。

    6. **标志** 占3位，但目前只有两位有意义。

        1. 标志字段的最低位记为MF，MF=1表示后面**“还有分片”**。

        2. 标志字段的中间位记为DF，意思是**“不能分片”**，DF=0时才允许分片。

    7. **片偏移 **占13位 是在较长分组的分片中，某片在原分组中的相对位置。偏移单位是8字节。除了最后一个分片外，每个分片的长度一定是八字节的整数倍。

    8. **生存时间 **占8位，缩写是TTL（Time To Live），是数据报在网络中的寿命。

        1. 最初设计TTL值的单位是秒。每到一个路由器就把TTL减去数据报在路由器所消耗掉的一段时间。当TTL值为0时，就丢弃这个数据报。

        2. 现在TTL字段的**功能**改为**“跳数限制”**（**但名称不变**），单位为**跳数**。每次转发时TTL减一。当TTL为0时就抛弃。

    9. 协议 占8位，表明数据报携带何种协议。

![image\.png](/Firefly/uploads/course-internet/image-27.png)

    10. **首部检验和 **占16位。这个字段只检验数据报的首部，但不包括数据部分。不采用复杂的CRC检验码而采用简单的计算方法：

        1. 在发送方，想把IP数据报首部划分为许多16位字的序列，并把检验和字段置0。用**反码算数运算**（按位正常加法，如果最高位产生进位，则最后得到的结果在最低位要进1）把所有16位相加后，把得到的和的**反码**写入检验和字段。

        2. 接收方接收到数据报之后，把首部的所有16位字再使用反码算数运算再加一次。将得到的和**取反码**，即得出接收方检验和的计算结果。若首部未发生任何变化，则此结果必为0，则保留；否则，认为有差错，则抛弃。

    11. **源地址 **占32位。发送IP数据报的主机的IP地址。

    12. **目的地址** 占32位。接收IP数据报的主机的IP地址。

    13. IP数据报首部的可变部分

3. IP数据报的首部的可变部分是个选项字段。选项字段用来支持排错、测量以及安全等措施，内容很丰富。长度可变，从1字节到40字节不等，取决于所选的项目。一些选项要1个字节，一些选项要多个字符。这些项目一个个拼接起来不需要分隔符，最后用全0的填充字段补齐为4字节的整数倍。

4. 增加首部的可变部分是为了增加IP数据报的功能，但也会增加每个路由器处理数据报的开销。

#### 掌握 IP 报文的校验和字段计算方法

- 计算步骤：

    1. 把 IP 头部按 16 位单位分割（校验和字段为 0）。

    2. 所有 16 位字相加，若产生进位则回卷（把高位加到低 16 位）。

    3. 对结果取反得到校验和。

- 示例：若 16 位字相加所得为 0x12345，则回卷为 0x2346（0x2345 \+ 0x1），校验和 = \~0x2346。

#### 理解并掌握子网掩码的作用与计算

1. 作用

    1. **声明网络地址与主机地址**：子网掩码通过二进制的逻辑运算，将IP地址划分为网络标识（Net\.ID）和主机标识（Host\.ID）。只有网络标识相同的两台主机才能在无路由的情况下相互通信。

    2. **划分子网**：子网掩码还用于将一个大的IP网络划分为若干小的子网络，这样做可以减少网络上的通信量，节省IP地址资源，并便于网络管理。

2. 计算

![image\.png](/Firefly/uploads/course-internet/image-15.png)

    1. 凡是从其他网络发送给本单位某个主机的 IP 数据报，仍然是根据 IP 数据报的目的网络号 net\-id，先找到连接在本单位网络上的路由器。

    2. 然后此路由器在收到 IP 数据报后，再按目的网络号 net\-id 和子网号 subnet\-id 找到目的子网。

    3. 最后就将 IP 数据报直接交付目的主机。 

#### 理解并掌握 IP 数据报分片原理，分片的 IP 报文的报头变化

- 原理与流程：

    1. 若数据报 \> 下一跳 MTU（最大传输单元） 且 DF=0（允许分片），路由器分片；否则若 DF=1，丢弃并发 ICMP。

    2. 每片保留相同 Identification，设置片偏移（以 8 字节为单位）和 MF 位。

#### 理解并掌握不同 ICMP 报文类型的作用

1. **ICMP差错报告报文**有**四种：**

    1. **终点不可达** 当路由器或主机不能交付数据报时就向源点发送终点不可达报文。

    2. **时间超过** 当路由器收到生存时间为零的数据报时，除丢弃该数据报外，还要向源点发送时间超过报文。当终点在预先规定的时间内不能收到一个数据报的全部数据报片时，就把已收到的数据报片都丢弃，并向源点发送时间超过报文。

    3. **参数问题** 当路由器或目的主机收到的数据报的首部中有的字段的值不正确时，就丢弃该数据报，并向源点发送参数问题报文。

    4. **改变路由（重定向）** 路由器把改变路由报文发送给主机，让主机知道下次应将数据报发给另外的路由器（找到了更好的路由）。

2. **ICMP询问报文**有**两种：**

    1. **回送请求或回送回答**ICMP回送请求报文是由主机或路由器向一个特定的目的主机发出的询问。收到此报文的主机必须给源主机或路由器发送ICMP回送回答报文。这种询问报文用于测试目的站是否可达以及了解二其有关状态。

    2. **时间戳请求和时间戳应答** 在ICMP时间戳请求报文发出后，就能够收到对应的ICMP时间戳应答报文。利用报文中记录的时间戳，发送方很容易算出当前网络的往返时延。

#### 掌握静态路由的概念，会正确设置静态路由表

1. 静态路由是网络中通过手动配置路由表来明确数据包转发路径的一种方式。其核心构成包括三个关键地址信息，每个地址在数据包转发中扮演着重要角色。

    1. **目标网络地址/子网掩码** 目标网络地址和子网掩码定义了需要到达的网络范围。例如，*192\.168\.2\.0/24*表示目标是*192\.168\.2\.0*网段。路由器通过匹配目标地址来决定数据包是否符合该路由条目。

    2. **出接口** 出接口指数据包从当前路由器的哪个物理或逻辑接口发送出去。例如，*GigabitEthernet 0/0*表示数据包将通过该接口转发到下一跳。对于点对点链路（如PPP链路），只需配置目标网络和出接口即可。

    3. **下一跳IP地址** 下一跳IP地址是数据包需要转发到的下一个路由器接口的IP地址。例如，*10\.2\.2\.2*表示数据包将被发送到与当前路由器直接相连的下一跳设备。在广播链路（如以太网）中，必须指定下一跳IP地址以明确转发目标。

2. 操作流程：

    1. 确定目标网络与下一跳地址或出接口。

    2. 在路由器/主机上添加静态路由（示例：`route add 10.0.0.0 mask 255.0.0.0 192.168.1.1`）。

    3. 验证路由：`traceroute` 或 `ping` 并检查跳数与出口接口。

#### 掌握 RIP 的工作原理

1. 路由信息协议RIP是内部网关协议IGP中最先得到广泛使用的协议。

2. RIP是一种分布式的**基于距离向量的路由选择协议**。

3. RIP要求网络中得到每一个路由器都要维护从它自己开始到其他每一个目的网络的距离记录。（是**一组距离**，即**距离向量**）RIP将**“距离（跳数）”**定义如下：

    1. 从一个路由器直接连接到网络的距离定义为1**（RIP度量）**

    2. 从一主机到非直接连接的网络的距离定义为所经过的路由器数加一。

    3. RIP 协议中的“距离”也称为**“跳数”**\(hop count\)，因为每经过一个路由器，跳数就加 1。

    4. 这里的“距离”实际上指的是“最短距离”。

    5. RIP认为一个好的路由就是它通过的路由器的数目少，即“距离短”。

    6. RIP允许一条路径最多只能包含15个路由器。

    7. “距离”的最大值为16时即相当于不可达。可见 **RIP 只适用于小型互联网**。

    8. RIP不能在两个网络之间同时使用多条路由。RIP 选择一个具有最少路由器的路由（即最短路由），哪怕还存在另一条高速\(低时延\)但路由器较多的路由。 

4. 三个要点：

    1. 仅和相邻路由器交换信息。

    2. 路由器交换的信息是当前本路由器所知道的全部信息，即自己限制的路由表。

    3. 按固定的时间间隔交换路由信息。

#### 理解并掌握 TCP 报文格式，掌握 TCP 报文各字段的作用与含义

![image\.png](/Firefly/uploads/course-internet/image-20.png)

TCP报文首部的前20个字节是固定的，后面有4n字节是根据需要而增加的选项（n是整数）。因此TCP首部的最小长度是20字节。

1. **源端口和目的端口字段**——各占 2 字节。端口是运输层与应用层的服务接口。运输层的复用和分用功能都要通过端口才能实现。

2. **序号字段**——占 4 字节。TCP 连接中传送的数据流中的每一个字节都编上一个序号。序号字段的值则指的是本报文段所发送的数据的第一个字节的序号。

3. **确认号字段**——占 4 字节，是期望收到对方的下一个报文段的数据的第一个字节的序号。

4. **数据偏移（即首部长度）**——占 4 位，它指出 TCP 报文段的**数据起始**处距离 TCP 报文段的起始处有多远。“数据偏移”的单位是32 位字（以 4 字节为计算单位）。 最大15\*4=60字节

5. **保留字段**——占 6 位，保留为今后使用，但目前应置为 0 。

6. **紧急 URG** —— 当 URG= 1 时，表明紧急指针字段有效。它告诉系统此报文段中有紧急数据，应尽快传送\(相当于高优先级的数据\) 。

7. **确认 ACK** —— 只有当 ACK= 1 时确认号字段才有效。当ACK= 0 时，确认号无效

8. **推送 PSH \(PuSH\) **—— 接收 TCP 收到 PSH = 1 的报文段，就尽快地交付接收应用进程，而不再等到整个缓存都填满了后再向上交付。

9. **复位 RST \(ReSeT\)** —— 当 RST= 1 时，表明 TCP 连接中出现严重差错（如由于主机崩溃或其他原因），必须释放连接，然后再重新建立运输连接。

10. **同步 SYN **——** **同步 SYN = 1 表示这是一个连接请求或连接接受报文。

11. **终止 FIN \(FINish\)** —— 用来释放一个连接。FIN= 1 表明此报文段的发送端的数据已发送完毕，并要求释放运输连接。

12. **窗口字段** —— 占 2 字节，用来让对方设置发送窗口的依据，单位为字节。窗口大小\[0\~2^16\-1\]

13. **检验和 **—— 占 2 字节。检验和字段检验的范围包括首部和数据这两部分。在计算检验和时，要在 TCP 报文段的前面加上 12 字节的伪首部。

14. **紧急指针字段** —— 占 16 位，指出在本报文段中紧急数

15. **选项字段** —— 长度可变，最长可达到40字节。当没有使用“选项”时，TCP的首部长度是20字节。TCP 最初只规定了一种选项，即最大报文段长度 MSS。MSS 告诉对方 TCP：“我的缓存所能接收的报文段的数据字段的最大长度是 MSS 个字节。”

16. **填充字段 **—— 这是为了使整个首部长度是 4 字节的整数倍。

#### 理解并掌握 TCP 连接建立的三次握手与连接释放的四次挥手

1. **三次握手**

![image\.png](/Firefly/uploads/course-internet/image-23.png)

    1. A 的 TCP 向 B 发出连接请求报文段，其首部中的同步位 SYN = 1 ，并选择序号 x ，表明下一个报文段的第一个数据字节的序号是 x \+ 1 。 

    2. B 的 TCP 收到连接请求报文段后，如同意，则发回确认，在确认报文段中使 SYN = 1 和ACK = 1 ，其确认号应为 ACK = x\+1 ，并选择序号 seq = y 。 

    3. A 收到此报文段后，向 B 给出确认，其 ACK = 1 ，序号应为 seq = x \+ 1 ，确认号应为ACK = y \+1 。 

    4. A 的 TCP 通知上层应用进程，连接已经建立。 

    5. 对ACK =1的确认报文，若不携带数据，序列号不会被占用 

——当运行服务器进程的主机 B 的 TCP 收到主机 A 的确认后，也通知其上层应用进程，连接已经建立。 

2. **四次挥手**

![image\.png](/Firefly/uploads/course-internet/image-34.png)

    1. 现在 A 的应用进程先向其 TCP 发出连接释放报文段，并停止再发送数据，主动关闭 TCP 连接。A 把连接释放报文段首部的 FIN = 1 ，其序号 seq = u ，等待 B 的确认。 

    2. B 发出确认，确认号 ack = u\+1 ，而这个报文段自己的序号 seq = v 。TCP 服务器进程通知高层应用进程。 从 A 到 B 这个方向的连接就释放了，TCP 连接处于**半关闭**状态。B 若发送数据，A 仍要接收。 

    3. 若 B 已经没有要向 A 发送的数据，其应用进程就通知 TCP 释放连接。 

    4. A 收到连接释放报文段后，必须发出确认。 在确认报文段中 ACK = 1 ，确认号 ack = w \+ 1 ，自己的序号 seq = u \+ 1 。 

    5. 必须等待 2\*MSL 的时间

#### 理解并掌握 TCP 拥塞控制原理和过程

![image\.png](/Firefly/uploads/course-internet/image-37.png)

1. **慢开始\(slow\-start\)**

    1. 在刚刚开始发送报文段时，先把初始拥塞窗口cwnd 设置为 1 至 2 个发送方的最大报文段 **SMSS\(Sender Maximum Segment Size\) **的数值。

    2. 在拥塞窗口达到慢开始门限之前，每经历一次确认，cwnd乘以2；达到慢开始门限之后，执行拥塞避免

2. **拥塞避免 \(congestion avoidance\) **

    1. 思路：让拥塞窗口 cwnd **缓慢地增大**。每经过一个传输轮次，拥塞窗口 cwnd \+= 1 ，避免出现拥塞。 

    2. 使拥塞窗口 cwnd **按线性规律缓慢增长**——也就是有 “**加法增大**” \(Additive Increase\) 的特点。 

    3. ——发送方网络出现拥塞时（**重传定时器超时**），无论在慢开始阶段还是在拥塞避免阶段： 

    4. **ssthresh = max\(cwnd/2\), cwnd = 1** ，之后**执行慢开始算法**。 

3. **快重传 \(fast retransmit\) **

    1. 发送方**只要一连收到三个重复确认**，就知道接收方确实没有收到报文段，因而应当立即进行重传（即**“快重传”**），这样就不会出现超时，发送方也不就会误认为出现了网络拥塞。 

    2. 算法可以让发送方**尽早知道发生了个别报文段的丢失**。——**快重传**算法首先要求接收方不要等待自己发送数据时才进行捎带确认，而是要立即发送确认，即使收到了失序的报文段也要立即发出对已收到的报文段的重复确认。

4. **快恢复 \(fast recovery\)**

    1. 当**发送端收到连续三个重复的确认**时，由于发送方现在认为网络很可能没有发生拥塞，因此现在不执行慢开始算法，而是执行快恢复算法 FR \(Fast Recovery\) 算法： 

    2. **慢开始门限 = 当前拥塞窗口 / 2： ssthresh = cwnd / 2 ； **

    3. **新拥塞窗口 = 慢开始门限： cwnd = ssthresh ； **

    4. ——**开始执行拥塞避免算法，使拥塞窗口缓慢地线性增大。 **

#### 理解并掌握 DNS 相关概念和工作原理

1. **域名系统DNS \(Domain Name System\)**是互联网使用的命名系统，用来把便于人们使用的机器名字转换为IP地址。许多应用层软件经常直接使用域名系统DN。虽然计算机的用户只是间接而不是直接使用域名系统。

4. 域名到IP地址的解析是由分布在互联网上的许多域名服务器程序（可简称为域名服务器）共同完成的。域名服务器程序在专设的结点上运行，运行该程序的机器称为**域名服务器**。

- 事务 ID：DNS 报文的 ID 标识。对于请求报文和其对应的应答报文，该字段的值是相同的。通过它可以区分 DNS 应答报文是对哪个请求进行响应的。

- 标志：DNS 报文中的标志字段。

![image\.png](/Firefly/uploads/course-internet/image-28.png)

    - QR（Response）：查询请求/响应的标志信息。查询请求时，值为 0；响应时，值为 1。

    - Opcode：操作码。其中，0 表示标准查询；1 表示反向查询；2 表示服务器状态请求。

    - AA（Authoritative）：授权应答，该字段在响应报文中有效。值为 1 时，表示名称服务器是权威服务器；值为 0 时，表示不是权威服务器。

    - TC（Truncated）：表示是否被截断。值为 1 时，表示响应已超过 512 字节并已被截断，只返回前 512 个字节。

    - RA（Recursion Available）：可用递归。该字段只出现在响应报文中。当值为 1 时，表示服务器支持递归查询。

    - Z：保留字段，在所有的请求和应答报文中，它的值必须为 0。

    - rcode（Reply code）：返回码字段，表示响应的差错状态。当值为 0 时，表示没有错误；当值为 1 时，表示报文格式错误（Format error），服务器不能理解请求的报文；当值为 2 时，表示域名服务器失败（Server failure），因为服务器的原因导致没办法处理这个请求；当值为 3 时，表示名字错误（Name Error），只有对授权域名解析服务器有意义，指出解析的域名不存在；当值为 4 时，表示查询类型不支持（Not Implemented），即域名服务器不支持查询类型；当值为 5 时，表示拒绝（Refused），一般是服务器由于设置的策略拒绝给出应答，如服务器不希望对某些请求者给出应答。

- 权威名称服务器计数：权威名称服务器的数目。

- 附加资源记录数：额外的记录数目（权威名称服务器对应 IP 地址的数目）。

    - 查询类型：DNS 查询请求的资源类型。通常查询类型为 A 类型，表示由域名获取对应的 IP 地址。

    - 查询类：地址类型，通常为互联网地址，值为 1。

    - 资源记录部分是指 DNS 报文格式中的最后三个字段，包括回答问题区域字段、权威名称服务器区域字段、附加信息区域字段。这三个字段均采用一种称为资源记录的格式，格式如图所示。

    - 类：地址类型，与问题部分中的查询类值是一样的。

#### 理解并掌握 HTTP 相关概念和工作原理

1. **HTTP **是**面向事务的 \(transaction\-oriented\) **应用层协议。使用 **TCP **连接进行可靠的传送。定义了浏览器与万维网服务器通信的格式和规则。是万维网上能够可靠地交换文件（包括文本、声音、图像等各种多媒体文件）的重要基础。它不仅传送完成超文本跳转所必须的信息，而且也传送任何可从互联网上得到的信息，如文本、超文本、声音和图像等。

2. **HTTP的主要特点**

    1. HTTP 使用了面向连接的 TCP 作为运输层协议，保证了数据的可靠传输。 

    2. HTTP 协议本身也是**无连接的。**（**所以虽然HTTP使用了TCP连接，但通信的双方在交换HTTP报文之前不需要先建立HTTP连接**）

    3. HTTP 是**无状态的 \(stateless\)**，简化了服务器的设计，使服务器更容易支持大量并发的 HTTP 请求。（**无状态的解释：同一个客户第二次访问同一个服务器上的页面时，服务器的相应与第一次被访问时相同\[假定现在服务器还没有把该页面更新\]，以为服务器不记得曾经访问过的这个用户，也不记得为该用户曾经服务过多少次。**）

3. **HTTP 的操作过程 **

![image\.png](/Firefly/uploads/course-internet/image-30.png)

    1. 非持续连接

        1. 客户（浏览器）每发送一个请求，Web服务器在发送响应后就关闭这条连接。

        2. 要向同服务器发送下一个请求需再建立TCP连接。

    2. 持续连接

        1. **非流水线方式**：客户在收到前一个响应后才能发出下一个请求。这比非持续连接的两倍 RTT 的开销节省了建立 TCP 连接所需的一个 RTT 时间。但服务器在发送完一个对象后，其 TCP 连接就处于空闲状态，浪费了服务器资源。

        2. **流水线方式**：客户在收到 HTTP 的响应报文之前就能够接着发送新的请求报文。一个接一个的请求报文到达服务器后，服务器就可连续发回响应报文。使用流水线方式时，客户访问所有的对象只需花费一个 RTT时间，使 TCP 连接中的空闲时间减少，提高了下载文档效率。

#### 掌握 HTTP 报文格式，掌握常见的请求头部信息、响应的状态码含义、以及响应头部信息

![image\.png](/Firefly/uploads/course-internet/image-26.png)

### 第五章 网络安全

#### 理解加密和解密的概念，理解对称加密和非对称加密的概念，熟知常用的对称加密算法 DES 和非对称加密算法 RSA

1. 解密和加密

    1. **加密：**加密是一种将信息（通常称为明文）通过特定的算法和密钥转换成无法被未授权用户理解的格式（称为密文）的过程。其主要目的是保护信息的机密性，防止信息在传输或存储过程中被窃取或泄露。

    2. **解密：**解密是加密的逆过程。它是使用特定的算法和密钥将密文转换回明文的过程。只有拥有正确密钥的用户才能成功解密，从而获取原始信息。

2. 对称加密和非对称加密

    1. 对称加密：

![image\.png](/Firefly/uploads/course-internet/image.png)

        1. 所谓对称密钥密码体制是一种**加密密钥**与**解密密钥**相同的密码体制。 

        2. 在这种加密系统中两个参与者共享同一个**秘密密钥**，如果用一个特定的密钥加密一条消息，也必须要使用相同的密钥来解密该消息。该系统又称为**对称密钥系统**。

    2. 非对称加密

![image\.png](/Firefly/uploads/course-internet/image-32.png)

        1. 使用**不同的加密密钥与解密密钥**，是一种“由已知加密密钥推导出解密密钥在计算上是不可行的”密码体制。 

3. **对称加密算法DES**

    1. 在加密前，先对整个明文进行分组。每一个组长为 64位。 

    2. 然后对每一个 64 位 二进制数据进行加密处理，产生一组 64 位密文数据。 

    3. 最后将各组密文串接起来，即得出整个的密文。使用的密钥为 64 位（实际密钥长度为 56 位，有 8 位用于奇偶校验\) 。

    4. **DES **的保密性仅取决于**对密钥的保密。**

    5. 目前较为严重的问题是 **DES 的密钥的长度**。

4. **非对称加密算法RSA**

    1. **基本原理**

        1. 密钥生成：

            - 首先，选择两个不同的大素数p 和q ，计算它们的乘积n=p×q 。n 的长度（以二进制表示的位数）就是密钥长度。

            - 计算欧拉函数φ\(n\)=\(p−1\)×\(q−1\) 。

            - 选择一个整数e ，满足1\<e\<φ\(n\) ，且e 与φ\(n\) 互质。

            - 计算e 关于φ\(n\) 的模逆元d ，即找到一个整数d ，使得e×d≡1modφ\(n\) 。

            - 公钥为\(n,e\) ，私钥为\(n,d\) 。

        2. 加密过程：

            - 假设明文为m ，满足0≤m\<n 。

            - 使用公钥\(n,e\) 对明文m 进行加密，得到密文c ，计算公式为：c=m^e mod n 。

        3. 解密过程：

            - 使用私钥\(n,d\) 对密文c 进行解密，得到明文m ，计算公式为：m=c^d mod n 。

    2. 安全性

        1. RSA的安全性基于大整数分解的困难性。给定两个大素数p 和q ，计算它们的乘积n 很容易，但反过来，给定一个大整数n ，要将其分解为两个素数的乘积却非常困难。目前，对于足够大的n （如2048位及以上），还没有有效的算法可以在合理时间内完成分解，因此RSA在理论上是安全的。

        2. 但也要注意，如果密钥长度不够长，或者在密钥生成过程中选择的素数不够随机、不够大，或者在使用过程中不遵循正确的操作规范（如重复使用密钥、泄露私钥等），RSA的安全性也会受到威胁。

    3. 优点

        - 安全性高：在密钥长度足够长的情况下，目前还没有有效的破解方法。

        - 易于理解和实现：其算法原理相对简单，基于一些基本的数学概念，便于开发人员实现和使用。

        - 支持数字签名：除了加密功能外，还可以利用私钥对消息进行签名，使用公钥验证签名，从而实现身份认证和数据完整性验证。

    4. 缺点

        - 计算速度慢：加密和解密过程涉及模幂运算，计算量较大，尤其是对于长密钥和大明文，速度相对较慢，不适合对大量数据进行加密。

        - 密钥管理复杂：虽然公钥可以公开，但私钥必须严格保密。在实际应用中，密钥的分发、存储和更新等环节都需要谨慎处理，以防止私钥泄露。

        - 对密钥长度要求高：为了保证安全性，需要使用足够长的密钥。随着计算技术的发展，为了抵御潜在的攻击，密钥长度需要不断增加，这进一步增加了计算和存储的负担。

#### 理解报文摘要的概念，熟知常用的摘要算法 MD5

1. 报文摘要（Message Digest）

    1. 是一种将任意长度的数据（报文）通过特定算法转换为固定长度输出的过程。这种输出通常被称为摘要、哈希值或散列值。报文摘要具有以下重要特性：

    2. 报文摘要的主要特性

        1. 确定性：相同的输入总是产生相同的摘要值。

        2. 单向性：无法从摘要值反向推导出原始数据。

        3. 抗碰撞性：

            - 弱抗碰撞性：给定一个输入，很难找到另一个不同的输入，使其摘要值与给定输入的摘要值相同。

            - 强抗碰撞性：很难找到两个不同的输入，使它们的摘要值相同。

2. MD5算法

    1. MD5（Message\-Digest Algorithm 5）是一种广泛使用的报文摘要算法，由Ron Rivest在1991年设计。它将输入数据（无论多长）转换为一个128位（16字节）的固定长度摘要值，通常以32位十六进制数表示。

    2. 工作流程

        1. 填充数据：

            - 首先，对输入数据进行填充，使其长度为512位的倍数。

            - 在数据末尾添加一个“1”位，然后添加若干“0”位，最后添加一个64位的长度值，表示原始数据的长度（以比特为单位）。

        2. 初始化缓冲区：

            - MD5使用4个32位的寄存器（A、B、C、D），初始值分别为：

            - 复制

            ```text
            A = 0x67452301
            B = 0xEFCDAB89
            C = 0x98BADCFE
            D = 0x10325476
            ```

        3. 主循环处理：

            - 将填充后的数据分成512位的块，每块进一步分成16个32位的子块。

            - 对每个512位的块，执行4轮操作，每轮包含16次迭代。每轮使用不同的非线性函数（F、G、H、I）和不同的常量。

            - 每次迭代更新寄存器A、B、C、D的值。

        4. 输出摘要值：

            - 处理完所有数据块后，将寄存器A、B、C、D的值拼接起来，形成最终的128位摘要值。

    3. MD5的特点

        1. 计算速度快：MD5的设计使其在当时的硬件环境下计算速度较快，适合对大量数据进行摘要计算。

        2. 输出固定长度：无论输入数据的长度如何，输出总是128位的固定长度，便于存储和比较。

        3. 广泛应用于校验：常用于文件完整性校验，通过比较文件的MD5摘要值来检测文件是否被篡改。

#### 理解报文鉴别的概念，知道报文鉴别与报文摘要的差别

1. **报文鉴别（Message Authentication） **是一种安全机制，用于验证报文的完整性和来源的真实性。它确保接收方能够确认报文确实是由声称的发送方生成的，并且在传输过程中未被篡改。报文鉴别通常结合了加密技术、摘要算法和密钥管理等手段，以提供可靠的身份验证和数据完整性保护。

2. 差别

    1. **报文摘要** 主要用于验证数据的完整性，通过哈希函数生成摘要值，适用于简单的完整性校验场景。

    2. **报文鉴别 **不仅验证数据的完整性，还验证数据的来源，结合密钥或数字签名提供更强的安全性，适用于需要高安全性的通信和身份验证场景。

#### 理解数字签名的概念，熟知常用的签名算法 RSA

1. 数字签名定义

    1. 数字签名是指发送方使用**数字摘要技术（如MD5哈希算法）**，对原始数据生成数字摘要，然后使用非对称密钥加密技术中的私钥（发送方私钥），加密这个数字摘要，得到数字签名。

    2. **数字签名的三个功能： **

        1. **实体鉴别：证明来源。 **

        2. **报文鉴别：防篡改，保证完整性。 **

        3. **不可否认：防抵赖。**

2. RSA算法

    1. RSA（Rivest\-Shamir\-Adleman）是一种广泛使用的非对称加密算法，也常用于数字签名。以下是RSA数字签名的详细过程：

        1. 密钥生成：

            - 选择两个不同的大素数 *p*  和 *q* ，计算 *n*=*p*×*q* 。

            - 计算欧拉函数 *φ*\(*n*\)=\(*p*−1\)×\(*q*−1\) 。

            - 选择一个整数 *e* ，满足 1\<*e*\<*φ*\(*n*\) ，且 *e*  与 *φ*\(*n*\)  互质。

            - 计算 *e*  关于 *φ*\(*n*\)  的模逆元 *d* ，即 *e*×*d*≡1 mod *φ*\(*n*\) 。

            - 公钥为 \(*n*,*e*\) ，私钥为 \(*n*,*d*\) 。

        2. 签名过程：

            - 发送方使用哈希算法（如SHA\-256）对消息 *m*  生成摘要值 *h*\(*m*\) 。

            - 使用私钥 \(*n*,*d*\)  对摘要值 *h*\(*m*\)  进行加密，生成签名 *s* ：

            - *s*=*h*\(*m*\)^*d *mod *n*

            - 将原始消息 *m*  和签名 *s*  一起发送给接收方。

        3. 验证过程：

            - 接收方使用相同的哈希算法对收到的消息 *m*  重新生成摘要值 *h*\(*m*\) 。

            - 使用发送方的公钥 \(*n*,*e*\)  对签名 *s*  进行解密，得到解密后的摘要值 *h*′\(*m*\) ：

            - *h*′\(*m*\)=*s^e *mod *n*

            - 比较 *h*\(*m*\)  和 *h*′\(*m*\)  是否一致。如果一致，验证通过；否则，验证失败。

#### 能综合应用加密算法、摘要算法、签名算法实现信息的保密通信、身份认证、报文完整性功能（参考 PGP 安全通信过程）

1. PGP（Pretty Good Privacy）安全通信过程

PGP 是一种广泛使用的加密软件，它综合应用了加密算法、摘要算法和签名算法，实现了信息的保密通信、身份认证和报文完整性功能。以下是 PGP 安全通信过程的详细步骤：

1. 密钥管理

    PGP 使用非对称加密算法（如 RSA 或 ECC）和对称加密算法（如 AES）来实现安全通信。每个用户都有一对非对称密钥：

    - 公钥：公开分发，用于加密和验证签名。

    - 私钥：严格保密，用于解密和生成签名。

2. 加密过程

PGP 的加密过程包括以下步骤：

1. 生成会话密钥

    - PGP 使用对称加密算法（如 AES）对消息进行加密，因为对称加密速度更快。

    - 随机生成一个会话密钥（Session Key），用于对称加密消息。

2. 对称加密消息

    - 使用会话密钥对消息进行对称加密，生成加密后的消息。

3. 非对称加密会话密钥

    - 使用接收方的公钥对会话密钥进行非对称加密，确保只有接收方能够解密会话密钥。

    - 将加密后的会话密钥附加到加密消息中。

4. 生成签名

    - 发送方使用哈希算法（如 SHA\-256）对原始消息生成摘要值。

    - 使用发送方的私钥对摘要值进行加密，生成数字签名。

    - 将数字签名附加到加密消息中。

5. 传输

    - 将加密消息、加密的会话密钥和数字签名一起发送给接收方。

3. 解密过程

接收方收到消息后，按照以下步骤进行解密和验证：

1. 解密会话密钥

    - 使用自己的私钥对加密的会话密钥进行解密，恢复会话密钥。

2. 对称解密消息

    - 使用解密后的会话密钥对加密消息进行对称解密，恢复原始消息。

3. 验证签名

    - 使用相同的哈希算法对解密后的消息重新生成摘要值。

    - 使用发送方的公钥对数字签名进行解密，得到原始摘要值。

    - 比较两个摘要值是否一致。如果一致，验证通过；否则，验证失败。

2. **具体实现示例**

假设 Alice 想要向 Bob 发送一条安全消息，以下是详细步骤：

1. Alice 准备消息

    - 消息内容：`Hello, Bob! This is a secret message from Alice.`

2. 生成会话密钥

    - Alice 随机生成一个会话密钥（例如 AES\-256 密钥）。

3. 对称加密消息

    - 使用会话密钥对消息进行 AES\-256 加密，生成加密消息 *C* 。

4. 非对称加密会话密钥

    - 使用 Bob 的公钥对会话密钥进行 RSA 加密，生成加密的会话密钥 *EK* 。

5. 生成签名

    - 使用 SHA\-256 对原始消息生成摘要值 *H*\(*m*\) 。

    - 使用 Alice 的私钥对摘要值 *H*\(*m*\)  进行 RSA 签名，生成签名 *S* 。

6. 传输

    - Alice 将加密消息 *C* 、加密的会话密钥 *EK*  和签名 *S*  一起发送给 Bob。

7. Bob 解密消息

    - Bob 收到消息后，使用自己的私钥对 *EK*  进行解密，恢复会话密钥。

    - 使用会话密钥对 *C*  进行 AES\-256 解密，恢复原始消息。

    - 使用 SHA\-256 对解密后的消息重新生成摘要值 *H*′\(*m*\) 。

    - 使用 Alice 的公钥对签名 *S*  进行解密，得到原始摘要值 *H*\(*m*\) 。

    - 比较 *H*\(*m*\)  和 *H*′\(*m*\)  是否一致，验证签名。

3. 功能总结

通过上述过程，PGP 实现了以下功能：

- **保密通信：**通过非对称加密会话密钥和对称加密消息，确保消息内容只有接收方能够解密。

- **身份认证：**通过数字签名，验证消息确实由声称的发送方生成。

- **报文完整性：**通过哈希算法生成摘要值，确保消息在传输过程中未被篡改。
